# 社区宠物到家服务平台｜需求阶段资料包 V0.1

**当前状态：讨论稿 / 原型预审；尚未开始正式研发。**

**[在线填写问卷入口](https://gordon310.github.io/petsCOM/)**：由平台运营方填写并导出答复，回传给问卷发起人。草稿仅保存在当前浏览器，页面不自动收集答复。

已确认试点所在地为**中国杭州**，两个试点均为**生活居民社区**。具体社区名称、场地条件和合作进度由平台运营方补充。

## 请按以下顺序使用

1. 阅读 `01_社区宠物到家_需求基线PRD_V0.1.md`，确认已有事实与尚未确认假设。
2. 使用 `06_社区宠物到家_小程序运营业务流程需求调查_V0.4.md`：平台运营方按服务安排、客户端、工作人员、后台、审核退回和异常售后六类流程填写。Grill-me 是每题里的现场场景追问。V0.1 至 V0.3 问卷保留为历史参考。
3. 由运营负责人牵头，调度、客服、接待站和专业服务负责人补充具体操作、责任岗位、处理时限及退回/异常的下一步。未定事项注明跟进人和日期。
4. 用浏览器打开 `社区宠物到家_低保真交互原型_V0.1.html`。可以切换居民、接待站、上门人员、总部四种身份；可以模拟预约、派单、完成履约、服务转介。
5. 参考 `03_社区宠物到家_UI信息架构与验收_V0.1.md` 逐屏提出“保留/修改/取消”意见。
6. 回收问卷和原型意见后，形成 PRD V1.0 与 UI V1.0 正式确认版，再评估技术方案、排期与 Codex 开发。

## 原型限制

- 采用内嵌 HTML/CSS/JS，可本地查看，无任何服务端与外部依赖。
- 所有社区、居民、宠物、人员、订单、状态均为模拟数据；价格未配置。
- 不执行真实付款、地图定位、直播、消息发送或后台数据存储，刷新后演示数据会重置。
- 原型不意味着用工关系、入户权、钥匙保管、专业医疗权限已获得许可。
- 不要填写真实住址、电话、门锁密码或敏感健康记录。

## 核心结论

项目的核心不是重新复制 TA岛，而是利用既有**公园/洗护/诊所/酒店/训犬场**作为专业服务中台，在社区设立线下接待站，结合上门履约和就业岗位。建议两社区试运营、总部统一管理，以订单质量、复购、转介率与岗位持续性衡量商业模式。
