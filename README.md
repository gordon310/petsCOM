# 社区宠物到家需求确认

本仓库用于两社区宠物到家服务试点的需求确认，本次由平台运营方定义未来小程序的应用与工作业务流程。运营问卷已回收，现依据正式答卷形成四端交互原型，供业务确认。

## 四端 UI 原型确认 V1.1

**[打开可交互的四端原型](https://gordon310.github.io/petsCOM/prototype/?v=1.1.0#/customer/home)** · [本版修改说明与待确认事项](doc/10_四端UI原型V1.1_修改说明与待确认事项.md)

包含用户小程序 18 页、接单小哥小程序 9 页、站点 PC 平台 10 页、总部 PC 后台 16 页，共 53 页。四端可继续同一笔本机演示订单，走通预约、审核、付款、派单、履约、客户确认及总部抽查；另含活动、转介、售后、追加账单和交接等操作示意。

原型仅用模拟资料。正式价格、时段、审批额度和商业口径标为待确认。评审意见在本机保存，可导出回传；支付、影像、消息均不真实执行。

## 已确认试点条件

- 试点所在地：中国杭州。
- 试点对象：两个生活居民社区。

平台方补充具体社区名称、合作进度及场地条件，不再选择国家/城市和社区类型。

## 填写运营业务流程调查

**[打开在线填写问卷](https://gordon310.github.io/petsCOM/)**

**[查看集中答卷记录与导出 CSV](https://gordon310.github.io/petsCOM/records.html)**

[业务流程问卷 V0.4](doc/06_社区宠物到家_小程序运营业务流程需求调查_V0.4.md) 包含 38 个运营问题，按服务安排、客户端、工作人员、后台、审核退回、异常售后六类流程分组。Grill-me 场景追问嵌入每题，运营方填写“谁负责、怎样操作、什么条件可以继续、退回或异常后怎么办”。

1. 运营负责人牵头，调度、客服、接待站及专业服务负责人补充自己熟悉的环节。
2. 选择业务安排并填写操作步骤、岗位与处理期限；未定事项注明跟进人。
3. 按前置条件逐轮确认，回收后汇总客户端路径、岗位工作清单和审核/异常流程。
4. 填写姓名/称呼及平台公司/团队，点击「提交答卷」，核实成功后即完成，无需另行回传文件。每份答卷分别留档；可多次提交修订，记录页筛选汇总并导出 CSV。

参考 TA 岛公开可核实的下单、客服沟通、入户和标准作业做法；本项目的审核、派单、退款等规则由运营方回答后确认。详细依据及候选主流程见 V0.4 文档。

**线上收集已启用。参与者无需 GitHub 账号；答卷作为公开需求记录留档，提交前须确认内容适合公开。测试答卷有单独标记，记录页默认排除。**

沿用 PAMFB 的网页提交→独立 Worker→GitHub 答卷记录→核实回执流程。多人和每次修订分别保存。新记录可能需几秒进入集中列表，可点击刷新。维护配置见 [部署说明](relay/README.md)，填写人不需要执行配置操作。

线上提交前，本机草稿和导出备份继续保留。V0.3 旧草稿保留在原存储位置，不按新题意自动套用；已有旧答复时可在页面导出旧版作为参考。

## 填写页维护

题目源为 V0.4 Markdown。运行 `python3 scripts/build-questionnaire.py` 生成 `questionnaire.json` 并检查题目与前置关系，运行 `node --check app.js` 检查脚本语法；`npm test` 检查提交校验、多人修订、重试查重、回执、异常和 CSV。GitHub Pages 从 `main` 分支根目录发布。
