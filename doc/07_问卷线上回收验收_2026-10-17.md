## 实施中保留的修正

1. 沿用 PAMFB 的提交→中转服务→GitHub 留档→回查→成功回执及记录页机制，问卷内容仅面向当前运营对象，不要求其回答技术问题。
2. 授权前先核对安装版本所需范围。Wrangler 4.151.1 发布脚本需要 workers_scripts:write；初始范围缺失导致发布失败，补齐后部署成功。授权链接超时应重新生成并等待回调。
3. GitHub 凭据限定 petsCOM 的 Issues 读写，由所有者在 Cloudflare 页面以 Secret 保存。代理可预填非秘密配置，不生成、复制、读取或传递令牌值；不复用通用 CLI 登录令牌。
4. 新记录列表可能比单条保存回执晚几秒更新。记录和查重直接读仓库 Issue 并识别答卷标记，避免依赖新记录的标签索引。单条回执按实际记录核实，列表必要时刷新，不据短暂缺失盲目重复创建。
5. 问卷脚本更新时刷新页面引用的版本标识，确保已经打开旧页面的浏览器在刷新后使用新提交逻辑。
6. 本机 DNS 缓存曾尚未识别新域名，正常 DNS 查询可以解析；使用正确 DNS 结果并保持证书校验核实服务，不能关闭 TLS 校验来“通过”测试。

## 维护边界

收集入口无需登录，是公开需求讨论方式。入口标记不是身份认证。后端只接受当前题号和选项，不接收任意目标仓库或正文。当前重试查重范围为最近 100 条仓库 Issue，规模扩大后再评估持久化幂等存储。后台令牌的到期与更新由账户所有者维护，不在仓库保存其值。
