## 已明确并落实

| 页面 / 事项 | V1.1 行为 |
| --- | --- |
| 四端服务名称 | “上门喂猫”统一改为“上门喂养”。品牌延续提供的 LOGO 驼色与鼠尾草绿。 |
| 首页商城入口 | 可进入商城说明页；没有真实地址时明确待配置，不设置假跳转。 |
| 洗护规格 | 服务目录区分小型犬 / 大型犬，预约选择规格；价格与体型标准待报价，不套用统一 99 元。 |
| 预约照护提醒 | 随所选宠物切换，提供档案编辑入口；“本次照护要求”单独填写，不覆盖长期档案。 |
| 预约审核 | 明示核对宠物资料、地址、入户条件、服务范围、可安排人员；审核后再确认费用付款。 |
| 多次服务 | 每次任务与报告独立，展示已结束、未服务、服务中、异常暂停和取消次数；不再宣称每次必须独立审核付款。整组计费规则未明确前不形成待付费用。 |
| 全中文订单状态 | “订单已生成待小哥接单”“订单结束待客户确认”等完整表述保持四端一致；后者明确为服务结束并提交报告后等待客户确认。 |
| 影像授权 | 客户下单时本人选择，拍照与直播独立且默认不授权；正式开始前可改，开始后改为停止影像 / 撤回处理工单，记录流转，不自动改写已发生授权。 |
| 活动 | 用户端分“现在可以报名”和“活动预热”；预热无报名、付款。后台可补资料、设置预热、开放报名；缺时间地点、组织人、报名条件、费用说明、取消退款规则、有效名额时拒绝开放报名。旧的不完整活动转预热，不填造正式条款。 |
| 售后 | 电话回访表单，电话必填且可修改；校验手机号或带区号座机。客户查看回访进度，站点和总部查看电话、责任岗位、处理记录；客户工单回访完成才能结案。提供一对一企微说明，不引导投诉客户入群。 |
| 宠物档案 | 可新增、编辑、删除确认。删除当前按归档方案演示，退出新预约选择；既有订单保留资料快照，名称、照护提醒不被后来编辑覆盖。 |
| 其他社区地址 | 可提交地址服务范围评估，不再一律按社区边界拒绝。客户查看记录，本站查看登记事项，总部记录距离、运力与责任站点评估；未确认前不收费派单。 |
| 追加服务 | 新需求与已确认服务的待付费用分开。客户填写项目、日期时段；总部核对原人员出勤、下班时间、请假和后续冲突，小哥本人确认或拒绝。申请不直接生成账单、强制续单或扣费；原人员不可接可调整时间 / 普通新预约。 |
| 我的 | 显示可编辑昵称；新增个人资料、我的优惠券独立页面。优惠券无真实资产 / 规则时展示空状态，不抵扣金额。 |
| 综合体预约 | 保留并显示“暂不确认”；等待补充原因，不认定取消。 |
| 评审入口 | 四端顶部新增“待确认事项”，可直接查看下列编号；评审意见仍在本机保存并可导出。 |

用户端由 15 页增加到 18 页；小哥 9 页、站点 10 页、总部 16 页，共 **53 页**。其他三端同步处理受影响流程，不代表其余页面已获得独立业务验收。

| D09 删除宠物 | 有进行中订单时可以删除档案吗？“删除”是否按归档、历史订单保留处理？ | 当前建议归档，停止新预约，履约和历史快照不删除；是否接受？ | 影响订单证据与资料保留，正式政策尚待批准。 |

## 复审顺序与验证

1. 用户端：切换宠物提醒 → 编辑档案 → 下单授权 → 审核说明 / 订单状态 → 报告确认。
2. 客服：填写演示电话提交 → 站点 / 总部查看同一工单 → 记录回访。
3. 追加：当前演示订单选择服务中订单 → 填新增需求 → 总部派单调度核对 → 小哥任务页回复 → 用户查看处理状态。
4. 活动：不完整草稿不能开放报名 → 补齐演示条款后可模拟开放；预热页不能报名。
5. 地址：登记其他社区意向 → 总部社区站点页跟进，检查没有直接形成收费订单。

自动检查：`npm test`，共 30 项通过，包含 53 页渲染、权限、服务全流程、授权限制、工单电话、档案快照、活动完整性、追加运力与旧数据兼容。页面还需业务方按实际规则确认；通过技术检查不等于业务验收。

## 演示边界与资料保留

订单、支付、退款、消息、电话、企微、定位、照片及直播均为模拟；不会真实执行。商城和企微真实入口尚未提供，优惠券规则未定。

订单、回访电话、地址意向和评审意见仅保存在当前浏览器。原型评审意见不自动集中回传，请导出给项目负责人。正式运营工单需要受控存储与权限，不能使用公开问卷 GitHub Issues 收集真实手机号或住址。原问卷集中收集流程未改动。

本次兼容原 V1.0 本机数据，不因界面升级重置订单或评审；旧订单未保存下单快照的，升级时保留演示档案参考并明确标为非原始下单记录，不补造真实历史。历史已确认账单不自动按新服务目录改价。
