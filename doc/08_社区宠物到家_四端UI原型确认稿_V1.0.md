## 依据与取舍

主要依据为运营业务流程问卷 V0.4 的正式答卷 [#12](https://github.com/gordon310/petsCOM/issues/12)，已答 37/38；截至本次读取共有 1 份正式答卷。测试答卷不参与需求判断。已有 PRD、信息架构、旧低保真原型和本机合作方案作为补充资料；存在冲突时，以正式运营答卷和后续明确确认优先。

试点地点为中国杭州，两个试点均为生活居民社区。真实社区名、场地地址和岗位负责人未提供，以 A/B 示例表示；所有人物、宠物、联系方式、订单与价格均为演示资料，不复用正式答卷参与人的身份资料。

已按正式答卷落实：不跨社区服务；平台指派、客户可申请换人；所有预约先审核再付款；影像先由主人独立授权；站点不保管钥匙或宠物；离场必须记录钥匙归还；主人可追加服务形成后续待付账单；客户先确认服务报告、平台另行抽查；群主活动报名收费；企业微信群客服跟进。

## 建议评审顺序

1. 用户从服务目录选择服务，填写宠物、地址、时间与次数，独立选择拍照/直播授权后提交申请。
2. 用“下一环节”或 PC 的“继续跨端流程”到总部审核；可通过或填写理由退回，用户补交后重新审核。
3. 用户确认演示报价并模拟付款，再由总部派单。候选人员须同社区、已审、有服务技能，且无已派演示任务时段冲突。
4. 小哥确认接单，逐项核对到场、主人入户授权和现场资料，执行分类清单，按授权记录演示照片。
5. 离场核对宠物、门窗、通知及钥匙归还，填写报告。清单或必需钥匙记录缺失时不能提交正常完成。
6. 客户确认报告、评价或联系客服；总部另行抽查、退回补充，补交复核保留原客户确认。
7. 站点试走辅助预约→居民本人确认及授权→总部审核。用评审工具切换 A/B 身份，核对本站资料和本人订单范围。
8. 查看多次任务、换人/拒单、现场暂停/恢复、主人追加/待付、活动草稿/发布/收费报名、专业转介、上岗审核、交接及售后审批/执行。

多次预约生成独立任务和报告入口。示例按每日一次、逐次审核/付款展示；**实际频次、套餐整体报价和付款口径属于待确认设计**。取消未履约任务保留已完成记录，费用通过售后另行核对，不自动套用退款比例。

## 审批与权限确认

- 用户仅看本人资料；工作人员仅看本人分配任务，完成/改派后收回入户和联络资料展示；站点仅看本站；总部按职责管理两社区。
- 身份与 A/B 切换是评审工具，正式系统不开放给普通用户自行换权限。
- 具体审核岗和金额授权尚未补充，原型暂由“总部有权岗位”承接，属于待确认方案。
- 费用调整分沟通核查→审批/退回→执行→回访结案。不能跳过审批执行，也不能把待执行方案直接结案；所有金额和执行均为本机模拟。
- 活动的站点/群主草稿→总部确认发布属于建议方案，需业务确认。

## 订单状态的完整中文说明

2026-10-23 根据业务确认补充。四端订单卡片、列表、筛选、详情、报告与后台概览统一使用以下完整表述。状态说明直接指出当前进度及处理责任，不使用“待审核”“待派单”“待结单”等独立简称。

| 订单状态名称 | 出现条件 | 接下来谁处理 |
| --- | --- | --- |
| 订单已代填待客户确认预约信息 | 站点已辅助填写，客户尚未确认 | 客户核对预约内容、入户及影像授权后提交 |
| 订单已提交待平台审核预约 | 客户已提交预约，平台尚未审核通过 | 平台核对宠物资料、地址、入户条件与人员安排 |
| 订单资料已退回待客户补充 | 平台已写明需补充的内容 | 客户补齐资料后重新提交，平台再审核 |
| 订单审核已通过待客户确认费用并付款 | 平台确认可提供服务，客户尚未付款 | 客户核对费用明细并付款 |
| 订单已付款待平台安排服务小哥 | 客户完成付款，平台尚未派人 | 平台调度核对资格、技能、社区和排班后派单 |
| 订单已生成待小哥接单 | 平台已为该订单安排服务小哥 | 小哥确认接单；如不能承接，说明原因并交平台改派 |
| 小哥已接单待按预约时间上门服务 | 小哥已确认承接，尚未开始服务 | 小哥按约上门、联系客户并核对入户授权 |
| 小哥已到场正在提供预约服务 | 到场、入户授权及现场核对完成 | 小哥按清单服务，客户可查看记录或联系客服 |
| 订单服务已暂停待平台处理异常 | 现场问题导致服务暂停 | 平台联系双方核实并决定恢复、改派或取消 |
| 订单结束待客户确认 | 小哥已结束服务并提交本次报告 | 客户核对报告，确认订单完成或申请售后 |
| 客户已确认订单服务完成 | 客户已确认本次服务报告 | 客户可评价或再次预约，平台另行抽查质量 |
| 订单已取消本次服务不再执行 | 本次未履约任务已按流程取消 | 客服核对取消记录及相关费用，不再安排该任务 |

“订单结束待客户确认”表示小哥已结束履约，订单仍等待客户确认；它与“客户已确认订单服务完成”分开记录。总部抽查独立跟进，不作为每单客户确认的前置条件。

报告状态独立写明“小哥尚未提交本次服务报告”“服务报告已提交待客户确认订单”“客户已确认服务报告订单已完成”“服务报告已退回待小哥补充”“小哥已补交服务报告待平台复核”“平台已完成服务报告抽查”。抽查退回或补交不会抹去客户已确认完成的订单事实。

## 使用和反馈

点击“记录评审意见”填写确认、需修改或暂不确认；**意见只保存于当前浏览器**。评审后点击底部“导出本机评审意见”，将 Markdown 文件交给项目负责人。不会自动发送或集中收集意见。正式需求确认以负责人汇总的结论为准，演示操作不表示业务确认。

演示进度保存在当前浏览器，“重置演示数据”恢复初始状态并保留评审意见。不同设备不共享原型进度；同源浏览器标签页共享本机存储。原问卷答卷与原型演示数据相互独立。
